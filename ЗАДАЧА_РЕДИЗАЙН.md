# Задача: переделать CodeTime под терминальный TUI — «точь-в-точь»

Сравнительное задание. Эталон — приложение `init.habits` (скриншот прилагается
отдельным файлом). Ниже всё, что нужно, чтобы повторить его вид и поведение
в трекере рабочего времени CodeTime.

---

## 0. Что это за проект

CodeTime — десктопный трекер времени за VS Code (Windows). Стек:

- Python 3.14, только стандартная библиотека для бэкенда;
- фронтенд — обычный HTML + CSS + JS **без фреймворков, без сборки, без CDN**;
- локальный HTTP-сервер на `127.0.0.1`, фронтенд открывается в WebView2 (Chromium ~120);
- PyInstaller собирает всё в один `CodeTime.exe`.

**Важно:** у WebView2 нет `window.prompt`, `window.alert`, `window.confirm` —
в собранном EXE они бросают исключение, и код падает молча, выглядя при этом
рабочим в обычном браузере. Только собственные модалки.

## 1. Референс: что именно повторяем

Скриншот `init.habits`. Структура сверху вниз:

```
┌───────────────────────────────────────────────────────────────────────────┐
│ [h] init.Habits [beta]  ·  habits  ·  stats ▾  ·  profile  ·  system  ·  help │
├────────────────┬──────────────────────────┬─────────────────────────────────┤
│ $ status       │ $ habits                  │ $ stats --overview     [close]  │
│ $ calendar     │                          │   ◇ lifetime overview           │
│ $ contributions│                          │   ♨ streaks                    │
│                │                          │   ⊞ data window                │
│                │                          │   ⇶ completion rates[30d]      │
│                │                          │   ⊞ day of week[30d]           │
│                │                          │   🏆 habit highlights[30d]      │
├────────────────┴──────────────────────────┴─────────────────────────────────┤
```

Три колонки, тёмная тема, моноширинный шрифт, панели в тонких рамках без

псевдографики (`▓░`, `◇♨⊞⇶`, `✓·`, `‹›`, `▾▸`).

## 2. Жёсткие ограничения

1. Никаких внешних зависимостей: ни JS-библиотек, ни CDN, ни веб-шрифтов.
   Только системный моноширинный стек.
2. Никаких `prompt()` / `alert()` / `confirm()` — **включая голые вызовы
   без `window.`**. Только собственные модалки приложения.
3. Никаких `eval`, `type="module"`, top-level `await`.
4. Никакого `innerHTML` с пользовательскими данными. Названия проектов и задач
   приходят из SQLite — вставлять только через `textContent`.
5. Не использовать `:has()` в правилах, отвечающих за раскладку.
6. Работать офлайн, без сети.

## 3. Файловая структура фронтенда

Четыре файла, каждый правит один человек — пересечений нет:

| Файл              | Что внутри                                                     |
|-------------------|----------------------------------------------------------------|
| `app.css`         | Всё оформление: токены, каркас, панель, строки, бары, вклад, модалки, обе темы, адаптив |
| `tui_widgets.js`  | Примитивы: `el`, `text`, `frag`, `clear`, `note`, `empty`, `panel`, `row`, `bar`, `cbx`, `chip`, `sec`, `modal`, `confirm`, `toast`, `wbars`, `fmt` → экспорт в `window.TUIW` |
| `tui.js`          | Оболочка: реестр экранов, меню, переходы, навигация по панелям, клавиатура, футер, тема, `TUI.api`/`TUI.post` → экспорт в `window.TUI` |
| `screens_a.js`    | Экраны «обзор» и «календарь»                                  |
| `screens_b.js`    | Экраны «проекты», «план», «задачи», «достижения», «настройки»  |

`dashboard.html` — только каркас: `<link app.css>`, четыре `<script>` в
фиксированном порядке (`tui_widgets.js` → `tui.js` → `screens_a.js` →
`screens_b.js`) и три пустых контейнера колонок. Никаких инлайновых стилей
и обработчиков в разметке.

> **Ловушка порядка загрузки.** Оболочка проставляет `TUI.el` и прочие
> примитивы **в момент своей загрузки**, а файлы экранов подключены после неё.
> Поэтому:
> - оболочка обязана стартовать по событию `load`, а не `DOMContentLoaded`
>   (иначе она успевает загрузиться раньше экранов);
> - файлы экранов **не кэшируют** `var el = TUI.el` на верхнем уровне — это
>   даёт `el is not a function`. Нужен вызов через обёртку
>   `function el(t,p,c){ return TUI.el(t,p,c); }`.

## 4. Дизайн-токены

Фон и текст — семейство GitHub Dark; акценты — янтарь и фиолетовый, как на
референсе. **Если есть доступ к скриншоту — снимай цвета пипеткой и ставь
фактические; ниже значения, восстановленные по нему.**

```css
--bg:        #0d1117;   /* фон окна */
--bg-panel:  #0d1117;   /* фон панели */
--bg-raised: #161b22;   /* активная строка, наведение */
--bg-inset:  #010409;   /* поля ввода, дорожка полосы */
--border:    #30363d;   /* рамка панели */
--fg:        #c9d1d9;   /* основной текст */
--fg-dim:    #8b949e;   /* приглушённый */
--fg-faint:  #6e7681;   /* разделители, декоративное */
--blue:      #58a6ff;   /* активный пункт меню, ссылки, «сегодня» */
--amber:     #d29922;   /* полосы, «Morning», заголовки секций */
--amber-br:  #e3b341;   /* заполненные полосы, вклад */
--violet:    #bc8cff;   /* «Evening», проекты */
--green:     #3fb950;   /* выполнено, хорошие значения */
--red:       #f85149;   /* опасное, удаление */
```

Шрифт **везде один** моноширинный:

```css
--font-mono: ui-monospace, 'Cascadia Mono', 'Cascadia Code', 'JetBrains Mono',
             'SF Mono', Consolas, 'DejaVu Sans Mono', 'Liberation Mono',
             'Courier New', monospace;
```

База 14px, `line-height: 1.45`. Числа — `font-variant-numeric: tabular-nums`,
иначе колонки прыгают. Скругления — **ноль везде**. Теней нет.

Контраст `--fg-dim` на фоне панели должен быть ≥ 4.5:1 в обеих темах.

## 6. Верхнее меню

```
[h] init.Habits [beta]  ·  habits  ·  stats ▾  ·  profile  ·  system  ·  help
```

- `[h]` — буква в квадратной рамке; рамку рисует CSS, в разметку кладётся
  **только буква**.
- `[beta]` — literal-текст в `[ ]`, приглушённый.
- Разделитель пунктов — `·` цвета `--fg-faint`.
- Активный пункт — `--fg`, с подчёркиванием и `▾`; остальные `--fg-dim`.
- Это настоящие `<button>`, фокус виден.
- Под 1000px остаётся `≡ меню`, который раскрывает список вниз.

Пункты CodeTime: `обзор · календарь · проекты · план · задачи · достижения ·
настройки`, горячие клавиши `1`–`7` (на узком экране цифры скрываются).

## 7. Панель

Заголовок **над** рамкой, а не внутри карточки.

```
.panel
  .panel-h
    .panel-t   → <i class="sig">$</i> + название
    .panel-x   → × или [close], прижато вправо
  .panel-b     → border 1px, padding 10px 12px
```

Активная панель: рамка `--border-lit` и `▌` слева в заголовке.

Заголовок секции внутри панели:

```
<span class="sec-i">◇</span><span class="sec-t">lifetime overview</span>
<span class="sec-w">[30д]</span>
```

`.sec` — это `<button>` с `aria-expanded`, сразу за ним сосед `.sec-b` с телом.

## 8. Строки данных

Сетка из трёх колонок, чтобы правый счётчик всегда стоял по правому краю, а
длинный текст обрезался многоточием и не ломал вёрстку.

```
<div class="row">
  <span class="row-k">подпись</span>
  <span class="row-dim">пояснение</span>
  <span class="row-v tnum">12.4 ч</span>
</div>
```

Пояснение-комментарий идёт строкой ниже:

```
// цель: 60%
```

> **Важно:** префикс `// ` добавляет CSS через `::before`. В разметку и в
> JS-текст он **не пишется**, иначе получится `// // цель`.

## 9. Чекбокс

```
[ ] не сделано      [✓] сделано
```

- Это `<button class="cbx" aria-pressed="true|false|mixed">`.
- **Глиф рисует CSS** (`::before` из `aria-pressed`). В содержимое элемента
  `[✓]` не кладётся — иначе будет `✓[✓]`.
- `aria-label` обязателен, для скринридера.
- Выполненная строка: `--fg-dim` + `line-through`, счётчик гаснет.
- Минимальная цель нажатия 28×28.

## 10. Полоса прогресса

```
[▓▓▓▓▓▓▓░░░░░░]  68%
```

`.bar` > `.bar-f` (`style.width = N%`), высота 8px, дорожка `--bg-inset`.
Состояния задаются **классами**, не инлайном: `bar--near` (60–99%),
`bar--over` (перерасход), `is-dim` (мало). Цвет — в CSS.

Подпись справа: `68% (4ч06м / 6ч)`.

## 11. Календарь месяца

Сетка 7×6, понедельник первым.

```
      пн   вт   ср   чт   пт   сб   вс
  ┌────┬────┬────┬────┬────┬────┬────┐
  │  3 │▓▓ 4│▓▓ 5│  6 │▓▓ 7│  8 │  9 │
```

- Номер сверху, под ним полоска активности за день.
- Пять уровней интенсивности — тот же ряд цветов, что у вклада.
- Нулевой день — только номер, приглушённый. Дни вне месяца — приглушённые
  и `aria-hidden`.
- Сегодня — рамка синяя.
- Шапка `‹  август 2026  ›`, стрелки переключают месяц и перезапрашивают данные.
- Клик по дню открывает модалку со списком проектов за этот день.

Разметка: `.cal` > `.cal-hd` + `.cal-wd` + `.cal-grid` > `.cal-cell`
(внутри `.cal-cell-n` и `.cal-bar`).

## 12. Вклад (тепловая карта года)

```
        янв   фев   мар   апр   май   июн   июл   авг
  пн   ▨▨▨▨ ▨▨▨▨ ▨▨▨▨ ▨▨▨▨ ▨▨▨▨ ▨▨▨▨ ▨▨▨▨ ▨▨▨▨
  ср   ▒▒▒▒ ░░░░ ▒▒▒▒ ▒▒▒▒ ▒▒▒▒ ▒▒▒▒ ▒▒▒▒ ▒▒▒▒
  вс   ░░░░ ░░░░ ░░░░ ░░░░ ░░░░ ░░░░ ░░░░ ░░░░
  // меньше ░ ▒ ▓ █ больше
```

- 7 строк × колонки-недели, сверху вниз по времени; сверху подписи месяцев.
- Пять ступеней: нет данных / 0.22 / 0.42 / 0.68 / полная.
- **Пороги ступеней — квантили по своим данным**, а не фиксиксированные
  минуты. Иначе вклад одинаково читается и у новичка, и у того, кто
  работает по 10 часов.
- Интенсивность задаётся общими классами `.i0`…`.i5` (`.i5` — верхняя).

## 13. Бар-чарт по дням недели

```
пн  ▓▓▓▓▓▓▓░░░░░░░░░░░  64%
вт  ▓▓▓▓▓▓▓▓▓▓▓▓▓░░░░  71%
пт  ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  88%
// лучший: пт (88%)   худший: вт (41%)
```

Длина полосы — ровно 20 символов: `Math.round(pct / 100 * 20)` символов `▓`,
остальные `░`. При 0% — ноль символов, не один. Метка дня — колонка 3ch,
процент — колонка 5ch справа.

## 14. Правая панель «статистика» — что в ней

Заголовок: `$ stats --overview` и `[close]` справа. Секции по порядку:

1. **◇ lifetime overview** — сводка за всё время: дней с данными, всего
   активного, среднее в день, лучший день.
2. **♨ streaks** — текущая серия, рекорд, лучший проект по серии.
3. **⊞ data window** — пресеты `[7д] [30д] [90д] [365д] [всё] [свой…]`.
   Активный — золотой. **Переключение реально перезапрашивает данные.**
4. **⇶ completion rates[30д]** — доля закрытых целей, среднее в будни,
   среднее в выходные.
5. **⊞ day of week[30д]** — бар-чарт из §13.
6. **🏆 habit highlights[30д]** — топ проектов и языки.

Секции сворачиваются кликом по заголовку, состояние — в `localStorage`.

## 15. Средняя панель — «задачи» (аналог «habits»)

```
  сегодня                      2 / 3   ▾
  [✓] ▸ дописать отчёт           45м
  [ ] ▸ рефакторинг роутера      90м
  [·] ▸ вычитать главу             —

  завтра                       0 / 2   ▾
  [ ] ▸ вёрстка шапки            30м
```

- Заголовок группы — кликабельная строка, сворачивает группу, стрелка
  `▾`/`▸` берётся из `aria-expanded`.
- **`.tgroup-a` — пустой спан**: глиф стрелки рисует CSS.
- Счётчик `[2/3]` справа от названия, приглушённый.
- Счётчик длительности: `45м`, `1ч30м`, `—` если минут нет.
- Пустая группа не показывается, кроме сегодняшней — там строка
  `// задач на сегодня нет`.
- Клик по строке переключает выполнение и реально пишет на сервер.
- Кнопки `+ задача` и `+ группа` — в стиле «тонкая рамка, без заливки».

## 16. Клавиатура

| Клавиши             | Действие                        |
|---------------------|---------------------------------|
| `1`…`7`             | экран из верхнего меню          |
| `←` `→`             | соседний экран / предыдущий месяц |
| `Tab` / `Shift+Tab` | следующая / предыдущая панель   |
| `↑` `↓`             | строка внутри активной панели   |
| `Enter` / `Space`   | переключить строку в фокусе     |
| `Esc`               | закрыть модалку, снять фокус    |
| `a`                 | новая задача                    |
| `d`                 | пауза / возобновление           |
| `r`                 | перезагрузить данные экрана     |
| `?`                 | палитра подсказок               |

- Глобальные клавиши **не срабатывают**, когда фокус в `<input>`,
  `<textarea>`, `<select>`, и пока открыта модалка (там только `Esc`).
- Активная панель — рамка `--border-lit` и `▌` в заголовке; строка курсора —
  фон `--bg-raised` и `▶` слева.
- Всё дублируется мышью. Клавиатура — ускорение, а не единственный способ.

## 17. Футер

Одна строка, по центру, мелко, приглушённо, перечисление сочетаний через `·`.
Меняет содержимое под активный экран: показывает клавиши этого экрана,
если он их задал.

## 19. Экраны CodeTime — что где должно быть

Трёхколоночный дашборд — только на экране «обзор». Остальные — обычные.

**обзор** — левая колонка: `$ статус` (русская дата, серия, полоса к дневной
цели, строка `// цель: N%`), `$ календарь` (§11), `$ вклад` (§12). Средняя:
`$ сегодня` — задачи (§15), `$ активность по часам`, `$ проекты сегодня`.
Правая: `$ статистика` (§14 целиком).

**календарь** — `$ календарь` над `$ вклад`, справа `$ сводка` с итогами
месяца.

**проекты** — `$ проекты` строками с долями и полосами, сортировка кликом
по заголовку; слева `$ итоги`, справа `$ топ-5`.

**план** — `$ цель` (название, дата, часов в день) и `$ шаги`: глифы
`[✓] / [·] / [ ]`, полоса прогресса, прогноз дат из `startDate`/`endDate`.
Добавление, правка, удаление, перемещение, готовый шаблон. Справа `$ темп`
и честный вердикт по `fit` — если `fit` равен `null`, сказать почему,
а не выдумывать оценку.

**задачи** — полноразмерная версия §15, с настоящими добавлением,
переключением и удалением через API.

**достижения** — `$ счёт` с общей полосой и сетка плиток; открытые — золотые;
фильтр-чипы по категории.

**настройки** — `$ отслеживание` (дневная цель, клики, клавиши, пауза,
автозапуск), `$ путь` (путь к БД), `$ версия`, `$ опасная зона`.

> **Кнопка «Установить» обновление должна быть заблокирована** с подписью
> `нужно подтверждение`. Она перезаписывает `CodeTime.exe` на диске, и
> один клик по ней не должен запускать перезапись.

## 20. Что проверять перед сдачей

1. `node --check` проходит на каждом JS-файле.
2. Ноль вхождений `prompt(` / `alert(` / `confirm(` / `eval(` — включая голые.
3. Все семь экранов открываются и показывают **данные**, а не пустоту.
4. Клик по строке задачи реально меняет состояние на сервере.
5. Переключение пресетов окна данных реально перезапрашивает `/api/overview`.
6. Пересборка страницы с нуля (F5) приводит к рабочему экрану — без
   «el is not a function» и прочих тихих падений.
7. Ни одного упоминания ИИ: ни чата, ни наставника, ни ключей OpenRouter,
   ни GitHub-токена. Эта часть приложения удалена, роуты `/api/mentor/*`,
   `/api/or/*`, `/api/team/*`, `/api/github/*` отвечают 404.
8. Ширины 320 / 768 / 1024 / 1440 / 1920: нет горизонтальной прокрутки,
   раскладка не разъезжается.
9. Светлая тема читается: тёмный текст на светлом фоне.
10. Пустая база (свежая установка, ноль строк во всех таблицах) не даёт
    ни пустых экранов, ни `NaN` — везде русская строка «пусто».
