# CodeTime — тихий трекер времени в VS Code (Windows)

**CodeTime** — маленькое фоновое Windows-приложение, которое тихо считает,
сколько времени вы проводите в VS Code, и складывает всё в локальную базу
SQLite. Никаких аккаунтов, никаких серверов, ничего не уходит в интернет.

Что умеет:

* **Активное время** — секунда считается активной, когда VS Code в фокусе
  (сколько времени вы реально провели в VS Code).
* **Пауза** — VS Code ЗАПУЩЕН, но не в фокусе: свернули окно, перешли на
  другое приложение или второй монитор. Когда VS Code полностью закрыт —
  время не идёт ни в актив, ни в паузу (никакой «самотёчной» паузы).
  «Активно + Пауза» = всё время работы в VS Code.
* **Проекты** — имя проекта определяется из заголовка окна VS Code
  (`index.ts - my-app - Visual Studio Code` → проект `my-app`).
* **Языки** — из того же заголовка берётся имя файла (`index.ts` →
  TypeScript) и считается время по языкам: в дашборде — панель
  «Язык» с топ-5 и полосками долей (js/ts/py/css/html/json/md/go/rust
  и т.д., прочие расширения — по имени).
* **Клики, символы, слова** — глобальные счётчики ввода, засчитываются
  только когда VS Code в фокусе (можно отключить в настройках).
* **Сессии** — непрерывные подходы к коду; обрываются после 5 минут без
  активных секунд или если окно VS Code пропало с экрана.
* **100 достижений** — время, действия, серии, проекты, режим дня, особые.
* **План обучения, синхронизированный с активным временем** — цель с датой
  («Перейти на React к 01.03») и шагами. Каждая активная секунда из
  «Обзора» (та же цифра, ничего дублирующего не считается) с даты старта
  плана последовательно «заливается» в шаги: первый шаг набирает свои
  часы, потом второй и так далее. У каждого шага — прогресс «X ч из Y»,
  статус (не начат / в процессе / время набрано) определяется сам;
  сверху — «сделано X ч из Y, осталось Z ч». Проекция дат и таймлайн
  считаются по остатку часов при вашем темпе (часов в день — вручную
  или автоматически по статистике за 14 дней).
* **Задачи** — карточки, сгруппированные по срокам: Просрочено / Сегодня /
  Завтра / Послезавтра / Скоро (пара дней) / Через неделю / Позже.
  «+ Добавить задачу» — с быстрыми кнопками срока (Сегодня, Завтра,
  Послезавтра, Через неделю, Через месяц) или точной датой. Режим
  «🗑 Удалить задачи»: кликаете по карточкам, выбираете несколько —
  удаляете одним подтверждением (или ✕ на карточке). Сетка «резиновая»
  и подстраивается под ширину окна. Задачи синхронизированы с
  календарём: добавленные в модалке дня появляются и здесь, и наоборот.
* **Обновление через GitHub** — Настройки → «Обновление приложения»:
  указываете свой репозиторий один раз, дальше «Проверить обновления» →
  «⬇ Обновить до vX.Y.Z» в один клик — приложение само скачает новый
  CodeTime.exe из последнего релиза, заменит свой файл и перезапустится.
* **Настоящее окно приложения, не сайт** — статистика открывается в
  нативном окне Windows (движок WebView2 — как у современных
  приложений): свой заголовок «CodeTime», своя иконка в панели задач
  и в Alt+Tab, никаких вкладок и адресной строки. Внутри — обзор
  (с графиком за выбранный период, топом языков и рабочих областей),
  календарь «Год» (хитмап как на GitHub) / «Месяц» (с суммами недель
  и точками у дней с задачами), проекты, план обучения, задачи,
  достижения, настройки; всё с тултипами при наведении.
  Полностью офлайн. Резервный способ обновления «Из файла…» тоже на
  месте: выбрали CodeTime.exe — приложение само заменит файл и
  перезапустится.
* **Сброс данных** — Настройки → «Опасная зона» → «Удалить все данные»:
  чистит всю статистику, задачи, план, опыт и достижения (настройки
  остаются), с подтверждением.
* **Ярлык на рабочем столе** — создаётся автоматически при запуске
  (можно пересоздать из меню трея).
* **Данные** — `%APPDATA%\CodeTime\codetime.db` (SQLite) + журнал
  `%APPDATA%\CodeTime\codetime.log`.

## 1. Установка Python 3.10+

1. Скачайте Python с https://www.python.org/downloads/ (кнопка Download Python 3.x).
2. Запустите установщик и **обязательно поставьте галочку
   «Add python.exe to PATH»** на первом экране.
3. Нажмите «Install Now».
4. Проверка: откройте командную строку (`Win+R` → `cmd`) и выполните
   `python --version` — должна показаться версия 3.10 или новее.

## 2. Сборка EXE

1. Откройте папку `tracker` (там, где лежат `codetime.py` и `build_exe.bat`).
2. Дважды щёлкните **`build_exe.bat`**.
3. Скрипт сам: проверит Python → установит зависимости
   (pynput, pystray, pillow, pyinstaller) → сгенерирует иконку →
   соберёт EXE и откроет папку `dist`.

   > Важно: сам `build_exe.bat` содержит только английский текст и
   > латиницу — это сделано специально, чтобы файл работал в любой
   > кодировке Windows. Не добавляйте в него русский текст: .bat с
   > кириллицей в UTF-8 ломает парсер cmd (ошибки вида «'...' is not
   > recognized» на обрывках слов) и сборка не выполняется.
4. Готовый файл: **`tracker\dist\CodeTime.exe`** — один файл. Размер
   больше, чем раньше (десятки МБ): внутри упакован собственный движок
   окна (WebView2) — браузер больше не используется. Первый запуск —
   5–10 секунд (распаковка), дальше быстро.
5. Если антивирус ругается на сборку — добавьте папку `tracker` в
   исключения и запустите батник ещё раз.

Пересборка после правок — просто снова запустите `build_exe.bat`.

## 3. Первый запуск

1. Запустите `CodeTime.exe`.
2. В системном трее (возможно, под стрелкой «^») появится иконка
   — тёмный квадрат со скобками и зелёными часами.
3. Автоматически откроется **нативное окно приложения** — свой
   заголовок «CodeTime», своя иконка в панели задач и в Alt+Tab,
   без вкладок и адресной строки.
4. На рабочем столе появится ярлык **CodeTime** — дальше запускайте
   приложение им (или из трея: правый клик → «Открыть статистику»).
5. Откройте VS Code и покодьте — статистика появится через несколько секунд.

## 4. Автозапуск с Windows

Два способа (работают одинаково):

* **Настройки дашборда** → вкладка «Настройки» → тумблер
  «Автозапуск с Windows» → «Сохранить».
* **Меню трея** → правый клик по иконке → галочка
  «Автозапуск с Windows».

В реестр пишется строка
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run → CodeTime`,
которая запускает `CodeTime.exe --no-browser` при входе в Windows.
Отключение тумблера удаляет строку.

## 5. Как устроено отслеживание

| Событие | Что происходит |
|---|---|
| VS Code в фокусе, есть ввод | активная секунда в текущий проект |
| VS Code в фокусе, ввода нет N минут | секунда в «паузу» (idle) этого дня |
| VS Code не в фокусе (свернут/другое окно/второй монитор) | секунда в «паузу» последнего проекта |
| Клик/клавиша при VS Code в фокусе | clicks++ / chars++, слова — по пробелу/Enter/Tab |

* Порог паузы — слайдер 5–10 минут в настройках, применяется сразу.
* Клик и клавиши считаются **только** когда окно VS Code активно и не
  наступил простой (детект простоя — системный `GetLastInputInfo`,
  то есть учитывается любой ввод по всему компьютеру).
* Смена дня — просто новые ключи в базе (по локальной дате).
* Язык файла определяется при каждой активной секунде из первого
  сегмента заголовка окна (имя файла до « - »); секунды копятся в
  таблицу `lang_stats(date, lang, active_sec)`.
* Достижения пересчитываются раз в 60 секунд и при открытии вкладки.

## 6. Обновление приложения через GitHub

Обновиться можно прямо из приложения — вручную файлы перекидывать не нужно.

**Разовая настройка (2 минуты):**

1. Создайте репозиторий на GitHub (например, `ivanov/CodeTime`) — можно
   приватный? Нет: для анонимного чтения релизов репозиторий должен быть
   **публичным** (данные с вашего компьютера туда не идут — только exe).
2. В приложении: **Настройки → Обновление приложения → GitHub-репозиторий**
   — введите `ivanov/CodeTime` и нажмите «Сохранить».

**Как выходить с новой сборкой:**

1. Соберите exe: запустите `build_exe.bat` → получите `dist\CodeTime.exe`.
2. На GitHub: **Releases → Draft a new release** → создайте тег `v1.6.1`
   (обязательно с буквой `v`, формат `vX.Y.Z`) → перетащите `CodeTime.exe`
   в поле вложений → опишите изменения → **Publish release**.
3. Всё. У пользователей (у вас) приложение при нажатии «Проверить
   обновления» увидит новый релиз и скачает exe одной кнопкой.

**Как это работает внутри:** приложение читает
`https://api.github.com/repos/<репозиторий>/releases/latest`, сравнивает
версию из тега со своей, показывает «⬇ Обновить до vX.Y.Z». По нажатию
скачивается exe-вложение релиза, проверяется подпись `MZ` (это exe), затем
работающий файл переименовывается в `CodeTime.exe.old`, на его место
кладётся новый, приложение перезапускается и через 15 секунд само удаляет
`.old`. Если обновление скачалось криво — замена откатывается, старый exe
остаётся на месте.

**Резервный путь** — «Из файла…»: скачанный где-то ещё CodeTime.exe можно
выбрать вручную, механика замены та же.

**Советы:** номера версий только увеличивайте (`1.6.0` → `1.6.1`), иначе
обновление не посчитается новым; exe называется `CodeTime.exe` — именно
такое вложение приложение ищет в релизе (любое `.exe` без «setup»/«old»
подойдёт, но с понятным именем лучше).

## 7. План (синхрон с активным временем) и задачи

Вкладка **«План»** — теперь живой счётчик, а не ручные галочки:

* **Синхронизация** — активные секунды из «Обзора» с даты старта плана
  (фиксируется автоматически при первом сохранении цели/шага) идут в шаги
  по порядку: пока первый шаг не «набрал» свои часы, второй не начинается.
  Пересчёт мгновенный и ничего не хранит — рассинхрон невозможен.
* **Итог** — большой процент, «сделано X ч из Y ч», «осталось Z ч»,
  чип «сегодня +N ч в план» и дата, с которой ведётся синхрон.
* **Шаги** — название и часы можно править на месте; у каждого шага
  прогресс-бар, «X ч из Y ч» и автоматический статус: «не начат» /
  «в процессе» / «✓ время набрано» (кнопки Старт/Готово больше не нужны).
  Стрелками шаг двигается вверх/вниз, ✕ — удаляется.
* **Проекция и вердикт** — даты считаются по остатку часов при темпе
  «часов в день» (0 = авто за 14 дней); зелёный «Успеваешь, запас N дн.»
  или красный «Опоздание на N дн. — нужно X ч/день».
* **Таймлайн** — та же полоса сегментов, что и раньше (ширина — по дням).

Вкладка **«Задачи»** — полностью переделана:

* **Группы по срокам**: Просрочено (красным) / Сегодня / Завтра /
  Послезавтра / Скоро — через пару дней / Через неделю / Позже.
  У каждой группы — количество, сумма минут и сколько невыполнено.
* **Резиновая сетка** — карточки сами подстраиваются под ширину окна
  (на десктопе крупные, в узком окне — в одну колонку).
* **Добавить задачу** — модалка с быстрыми сроками: Сегодня / Завтра /
  Послезавтра / Через неделю / Через месяц (или точная дата), название
  и минуты.
* **Удалить задачи** — режим массового удаления: кликаете по карточкам
  (они подсвечиваются красным), внизу «Удалить выбранное (N)». На каждой
  карточке есть и быстрый ✕ (с подтверждением).
* **Синхрон с календарём** — задачи, добавленные в модалке дня календаря,
  появляются здесь, и наоборот; в месячном календаре у дней с задачами
  зелёные точки.

## 8. Где хранятся данные

* База: `%APPDATA%\CodeTime\codetime.db` — обычный SQLite-файл.
* Журнал: `%APPDATA%\CodeTime\codetime.log`.
* Кэш окна приложения: `%APPDATA%\CodeTime\ui-profile` — можно удалять,
  пересоздастся сам (там только настройки окна, не данные).
* Трей-меню → **«Открыть папку данных»** откроет эту папку.

Ничего не отправляется в интернет: сервер слушает только `127.0.0.1:5731`.

## 9. FAQ

**При запуске .bat летят ошибки «' loads' / 'pillow' / 'dden-import' is not recognized».**
Значит, батник был сохранён в UTF-8 с русским текстом и/или с `chcp 65001` —
парсер cmd сбивается и выполняет обрывки строк. Используйте оригинальный
`build_exe.bat` из репозитория (он только из ASCII-символов) — либо, если
редактируете его сами, не пишите кириллицу и сохраняйте файл в кодировке
ANSI/UTF-8 **без BOM** с переводами строк CRLF.

**Сборка падает на шаге иконки с ошибкой `No module named 'PIL'`.**
Так бывало в старой версии батника (иконка генерировалась до установки
зависимостей). В текущем `build_exe.bat` зависимости ставятся первыми —
просто запустите его ещё раз.

**Окно статистики — точно не браузер?**
Да, это нативное окно приложения (движок WebView2 — системный
компонент Windows). Своё окно, своя иконка в панели задач, браузер
не открывается. Редкий запасной сценарий: если компонент WebView2
вдруг недоступен, приложение само откроет статистику в отдельном
окне без адресной строки (Edge/Chrome в режиме приложения) — на
трекинг это не влияет.

**Ярлыка на рабочем столе нет.**
Он создаётся при каждом запуске CodeTime.exe (и самообновляется при
переносе exe). Можно и вручную: трей → правый клик → «Ярлык на
рабочем столе». Если рабочий стол под OneDrive — ярлык всё равно
найдётся, путь берётся у системы.

**Windows SmartScreen предупреждает о неизвестном приложении.**
Нажмите «Подробнее» → «Выполнить в любом случае». EXE подписан не сертифицированным ключом (его нет) — это нормально для самосборных программ.

**Антивирус ругается на глобальные хуки клавиатуры/мыши.**
pynput использует стандартные Windows-хуки (`SetWindowsHookEx`), некоторые
антивирусы на это реагируют. Добавьте `CodeTime.exe` и папку
`%APPDATA%\CodeTime` в исключения антивируса.

**Почему прогресс плана не растёт, хотя я кодил?**
Прогресс плана считается от даты синхронизации (показана чипом «синхрон с …»).
Время до этой даты в план не заливается. Проверьте также, что день вообще
попал в статистику: активные секунды пишутся, только когда VS Code был в фокусе.

**Кнопка «Проверить обновления» пишет «нет связи с GitHub».**
Проверьте интернет. Если GitHub недоступен (блокировки/офисный фильтр) —
обновитесь резервным способом «Из файла…» или скачайте exe вручную со
страницы релизов.

**Как перенести данные на другой компьютер?**
Закройте CodeTime (трей → «Выход»), скопируйте всю папку
`%APPDATA%\CodeTime` на новый компьютер в то же место, запустите EXE.

**Как полностью удалить CodeTime?**
1. Трей → правый клик → «Выход».
2. Если включён автозапуск — снимите галочку в трее/настройках ДО выхода
   (или удалите строку `CodeTime` в `HKCU\...\Run` через `regedit`,
   либо в Диспетчере задач → вкладка «Автозагрузка»).
3. Удалите `CodeTime.exe` и папку `%APPDATA%\CodeTime`.

**Порт 5731 занят / открылось второе окно браузера.**
Значит, CodeTime уже запущен — просто откройте статистику из трея.

**Не считаются клики/символы.**
Проверьте в настройках тумблеры «Считать клики» и «Считать клавиши и
слова». В окне сборки из-за OneFile иногда помогают исключения антивируса.

## 10. Запуск без сборки EXE (для разработки)

```
cd tracker
python -m pip install -r requirements.txt
python codetime.py
```

Остановка в консоли — `Ctrl+C`.

## 12. API локального сервера (для любопытных)

| Маршрут | Что возвращает |
|---|---|

## 13. Наставник — ИИ-помощник по фронтенду (с v1.9.0)

Вкладка **«Наставник»** — личный ИИ-наставник и строгий ревьюер вашего
фронтенд-кода, встроенный в CodeTime. Работает с любым OpenAI-совместимым
API (Z.ai / OpenRouter / VseGPT / свой сервер) и умеет:

* **Чат** — разбор кода по порядку (баги → семантика → адаптив → CSS),
  с ДО/ПОСЛЕ на вашем же коде. Кнопки: «Разбор кода», «Разбор макета»,
  «Конец дня» (вердикт + оценка + журнал + задача на завтра), «Задача на завтра».
* **Фото макета** — прикрепите скриншот (кнопка 📎 или Ctrl+V): наставник
  опишет блоки, сетку, чего не хватает, и даст план вёрстки
  (нужна vision-модель, например `glm-4.5v`).
* **Чтение GitHub** — подключите read-only fine-grained токен, и наставник
  сможет сам тянуть ваши файлы и коммиты: напишите в чате
  «проверь мой код, файлы: index.html, styles/main.css».
  Токен даётся ТОЛЬКО на чтение одного репозитория, приватный подойдёт.
* **План и Журнал** — файлы `plan.md` и `journal.md`: наставник читает их
  в начале каждого разговора и сам дописывает журнал в конце сессии.

### Память наставника

Всё хранится в обычной папке `%USERPROFILE%\CodeTimeMentor`:

```
C:\Users\<вы>\CodeTimeMentor\
  config.json   — подключение к ИИ и GitHub (ключи)
  role.txt      — роль наставника (характер и правила, можно править)
  journal.md    — Журнал прогресса: итоги сессий, память между чатами
  plan.md       — дорожная карта обучения
  history\      — переписка по дням
  layouts\      — присланные фото макетов
```

Чат потерялся? «Наставник → Журнал → Копировать» и вставьте текст первым
сообщением в новый чат — наставник продолжит с того же места.

### Первый запуск — 5 минут

1. Откройте вкладку «Наставник» — мастер сам подскажет два шага.
2. **Ключ ИИ**: z.ai (GLM — дёшево) / openrouter.ai (есть бесплатные модели) /
   vsegpt.ru (карты РФ). Вставьте ключ в «Настройки», нажмите «Проверить ключ».
3. **GitHub** (по желанию, для разбора кода из репозитория):
   Settings → Developer settings → Personal access tokens → Fine-grained →
   Generate new token → только Contents: **Read-only** на один репозиторий.
4. Жмите «Конец дня» или присылайте код — всё остальное наставник сделает сам.

Ключи хранятся только на вашем ПК (`config.json`), запросы к ИИ идут напрямую
с вашего компьютера в выбранный API. Сервер CodeTime по-прежнему слушает
только `127.0.0.1`.
